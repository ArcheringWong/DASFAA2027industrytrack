# D3 统一变形性质：非新增输出前缀

**事前冻结日期：2026-11-14；本文件先于 D3 主要测试代码和新执行结果。** 研究范围是字段游标增量抽取在稳定、有限、按声明顺序提供的批次上是否过早停止；不讨论 WAL/CDC 或持久检查点提交本身。

## 性质

令历史 `H=(P,B,C)`，`P` 为已完成的先前同步与目标确认身份，`B=[b1,…,bn]` 为本轮源端按接口承诺提供的批次，`C` 为产品读取契约。独立源日志按 `C` 算出本轮必须可达的**新身份** `E(H)`。令 `N` 为插入当前批次序列开头的非空前缀批次。变形 `T_N(H)=(P,N◦B,C)` 只在以下全部条件成立时合法：

1. `P` 和本轮原有合格记录的 `id`、游标、提交/可见性、相对顺序、读取参数与目标写入语义不变；全部在同步开始前可见。
2. `N` 每条记录在 `C` 下**不增加必须确认的新身份**。本阶段只接受两种可审计证据：其身份已由 `P` 成功确认且闭区间允许边界重读、产品按主键去重；或游标为空且 `on_cursor_value_missing="exclude"` 明确排除。不能把任意旧游标回填、未确认边界记录或空值 `include` 当中性。
3. 插入后非空游标仍满足声明的升/降序；相等游标的相对顺序由受控源固定，不能依赖数据库未指定的排序。源接口的批次覆盖没有遗漏，格式/批次形态是产品支持的输入；若有界，原有合格游标仍处范围内。
4. Oracle 独立计算且验证 `E(H)=E(T_N(H))`，不是因为两个实际输出相等才称等价。

**关系：**若基线历史完整确认 `E(H)`，合法变形后也须完整确认同一集合。具体判定不止看两次目标差异：分别以源身份 oracle 检查两次真实目标确认集合。`P` 中已确认身份可重复读取；目标只比较逻辑 ID 集，重复计数不构成遗漏。若目标采用 upsert/merge，重复输出可能被覆盖，本性质仍只判断身份完整性，不声称识别重复发射。

## 结果状态

- `PASS`：两次执行成功，预期集合相同，基线与变形目标均包含承诺 ID。
- `TRUE_VIOLATION`：基线完整，合法变形执行成功，但变形目标缺承诺 ID；记录缺失 ID、首次停止的批次、检查点/上界状态。
- `INVALID_TRANSFORMATION`：任一合法性条件不成立或两个独立预期集合不同；**拒绝执行连接器**。
- `INCONCLUSIVE`：基线本身缺记录、目标确认不可观测、排序契约不足，或只发生允许重复而无法判断新增遗漏。可另报告基线自身异常，但不归因于变形。
- `EXECUTION_ERROR`：被测运行抛异常或环境错误，保存原始错误，不写成静默漏数。

## 两个合法实例（同一关系，不按 Issue 编号分支）

**已确认边界前缀：**`P` 已确认 `(id=1,c=1)`，闭区间、降序、主键 `id`；本轮基线仅提供新 `(id=2,c=1)`。`T_N` 在前面加一批已确认 `(id=1,c=1)`，页大小均为 1。受控源固定相同游标的顺序。两次最终逻辑目标都应为 `{1,2}`，本轮必须新增 `{2}`。在真实 dlt 1.31.0/1.32.0 分别检验。

**排除空游标前缀：**无 `P`，Arrow 批次、升序、有上界 10、空值策略 `exclude`；基线只有有效 `(id=3,c=5),(id=4,c=6)`。`T_N` 前插一批 typed `ts=NULL` 的 `(id=1),(id=2)`。有效非空序列与源可见性不变，两次预期均 `{3,4}`。在真实 dlt 1.32.0 检验；不把空记录的消失判故障。

## 不合法或未测试的变形

空游标 `include`、未确认但同游标的新身份、在未承诺回填的范围内新增旧游标、改变 `row_order`/`end_value`/主键、将同游标交给不稳定的数据库排序、改变原记录提交时间或漏掉页、把 dict 与 Arrow 混入不保证兼容的单次读取，都不属于本关系。单纯改页大小或批次划分只有在源覆盖、排序、格式和原始记录完整相同且两次 oracle 集合相同时才可能等价；本阶段主要实现“合法非新增输出前缀”，**不声称所有重分页天然合法**。
