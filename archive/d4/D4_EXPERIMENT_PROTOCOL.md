# D4 公平比较协议（事前冻结）

## 范围与顺序

先复制 D3 执行器到 D4 并建立共享真实 dlt 适配器与独立源身份 oracle；A 为清晰的显式 pytest 回归，B 为 Hypothesis `RuleBasedStateMachine` 操作序列，C 为 D3 的条件化中性前缀关系。公共模块的初始化成本向三者共同计费，方案专有代码另计。初始套件含两种已知机制、修复版和正常/非法对照。初始代码及输入保存 `snapshots/base/`；每任务从其副本另起 `snapshots/Tn/`，以统一 diff 记录修改。

先运行初始 A/B/C，再对 T1、T2、T3 各自实现并运行真实 dlt。版本 1.31.0/1.32.0 与 D3 锁定一致。单任务执行预算为每方案每版本最多 8 个真实场景，B 的状态机采用固定例子和有限生成步数；不以随机命中率竞赛。正常控制、非法和不确定状态遵循 D3 定义。若执行器或 oracle 公共代码需修改，在成本表显式计入，不能藏在共享模块。

## 指标与判读

按 git 风格统一 diff 统计每个 A/B/C 任务的增加、删除/修改行及改动文件；记录新增参数、规则、复制用例和共享模块变更。执行器包装 `pipeline.run()` 计数，保存每场景耗时、实际页/批、目标 ID、独立预期和错误。A 的已知故障用预期失败断言，不令 pytest 套件错误退出；B/C 同理。所有方案必须暴露原始轨迹。比较诊断时检查实际字段，不根据报告文案长短评分。

耗时为本地一次真实执行的描述值，不是显著性或开发者工时。相同源历史、版本、契约和 oracle 才可比较；C 成对需要额外运行，按真实调用数收费。B 状态机须包含先前同步、添加边界记录、分页、空游标批、Arrow、上界等操作，允许使用固定见证使已知故障确定可检，同时保留一般规则；不把固定见证冒充自动探索。开发中修错与最终运行区分，所有主张以最后保存的原始轨迹为准。
